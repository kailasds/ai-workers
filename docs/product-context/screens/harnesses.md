## 0. What a harness is (CONFIRMED)
An **execution adapter**: software packaged as the **serving image** a Worker runs on ("a harness is not a tool the runtime calls — it *is* the serving image"). Choosing one changes what the Worker *is*. It declares a **manifest** (id, name, version, vendor, description, worker types, ladder, contract major/minors, serve bind/port/base path, **stages** (key, title, "adds", pipeline, produces metrics, requires sidecars, after), **evidence metrics** (name, type, description — "reported by the harness · not counted"), extension events (with learning signal), runtime needs (CPU, memory MiB, ephemeral storage GiB, sidecars, actions it may ask for, egress: model gateway, package mirrors, other), settings, pages it serves, vocabulary, licence). The platform relates to it through the **Harness–Worker Contract** (`/hwc/v1`, contract major 1, minors e.g. 0,1,3).
`PackagedHarness.availability`: `available | recipe_only | planned` ("a harness can be chosen while it cannot yet be launched"). Image pin state: digest-pinned or not ("No image pinned in this environment").

## 1. Catalogue — `/harnesses`
**Purpose:** "Execution adapters available to this platform."
**Info (per harness):** display name, key, vendor, summary, availability + detail ("Ready to use in this environment."), manifest version and "N stages" ("No manifest recorded"), certification state, used-by count ("Usage not reported" when null), image pin (digest), manifest source (`reviewed_copy`) and digest; expandable manifest facts (`ManifestFacts` — shared with the harness page so they cannot disagree).
**Example (mock):** "Integration Modernisation Harness" (`codeplus-integration-modernization`), TCS, manifest `modernization-harness` v2.2.0, worker type integration-modernization, stages conversion → unit-testing → … ; serves 127.0.0.1:8100 /hwc/v1; produces functional-equivalence, specs-coverage, evals-pass-rate. Also "Quality Engineering Harness" (used in mock Workers).
**Actions:** open a harness; "Certification guide" → `/harnesses/certify`; empty state "No harnesses registered. Quick start". Error: "Could not load the harness catalogue."

## 3. Certify — `/harnesses/certify`
"Certify a harness": a five-step guide (it **sends nothing**): **Build** (harness team: run function + manifest with the Python SDK, build the image) → **Check** (run the conformance suite against the image; shell command shown) → **Review** (read the report; fix & re-run; "Only a version that passes can be certified.") → **Request certification** (send the report to a maintainer yourself; "The person who ran the suite cannot certify their own report.") → **Certify** (maintainer, on the prod host in their own terminal, runs `scripts/certify_harness.sh`, which re-runs the suite against the same image, asks for confirmation, and records who certified and when). A harness+version select shows instructions; **Harness status** table: Harness · Version · State · Next step. Footnote: "Compose shows each version's state. It does not refuse an uncertified version yet. Conformance is evidence, not a security boundary: the Worker's isolation holds whether or not a harness passed."

## 4. Conformance reports — `/harnesses/conformance` and `/…/:reportId`
List of cards (one per harness version): verdict first ("Certified · {date} · {by}" / "Failed · N checks failed" / "Passed · certification pending" / **"Certification record missing"** when the report says admitted but no record exists — "a source contradiction is said, never resolved into a reassuring state"), **fifteen checks as marks**, what the team's code gained for the SDK (Untouched / Edited / Added for the SDK files with purposes), source on GitLab at the commit the image was built from. States: `admitted | checked | rejected`; check result `pass | fail | not_applicable`; a check the report does not carry is **pending**, never pass/fail.
Report page: callout (Certified / Conformance failed / Certification record missing / "Conformance passed · certification pending" + the certify command); checks list filterable by group and result, each with Requirement, Observed result (log), Source; table Check · Group · Result; Report id, Image digest, Recipe, Suite·contract, Source commit, Run (time range, by), Certified (when, by); **Download report JSON**. Empty: "No report recorded for this image." / "Could not load the report."

## 5. SDK reference — `/harnesses/sdk/:page`
Documentation pages, 4 groups: **Start** (Overview, Quick start) · **Interfaces** (Run context, SDK calls, Learning and Sentinel, Run lifecycle, Rules) · **Python SDK** (harness-app, run, run-context, okf, manifest) · **Reference** (conformance, api, schemas). Left navigation (select on phones), previous/next, code samples with copy, schema views, diagrams (lifecycle sequence, overview figure). Pages with `needsContract: true` render from `GET /harness-contract` (cached; `forgetHarnessContract()`), others draw immediately. Error: "Could not load the contract." This is **developer documentation**; a new UI may host it however it likes but must keep: page set, deep-linkable page keys, anchors like `/harnesses/sdk/calls#emit`.
